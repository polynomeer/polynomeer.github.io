# Supabase Comments Design

This document defines the first-stage comment migration from Giscus to Supabase.

## Goal

Replace GitHub Discussion embed comments with a site-owned comment system that:

- uses GitHub login through Supabase Auth
- stores comment data in Supabase
- works on static-hosted Jekyll pages
- creates a clean base for later notification features

## Stage 1 Scope

Stage 1 includes:

- GitHub OAuth sign-in via Supabase Auth
- top-level comments only
- post-scoped comment listing
- comment creation
- deleting your own comment

Stage 1 does not include:

- replies
- mentions
- moderation queue
- push notifications
- email notifications

## Why This Replaces Giscus

Giscus is low-maintenance, but the data and workflow are tied to GitHub Discussions.

Supabase comments trade simplicity for ownership:

- comments live in the blog's own data model
- UI can be customized directly
- notifications can be added later without changing providers again

## Configuration Model

Use the existing comments provider switch:

```yml
comments:
  provider: supabase
  supabase:
    url: https://YOUR_PROJECT.supabase.co
    anon_key: YOUR_PUBLIC_ANON_KEY
    table: post_comments
    key_column: post_path
    auth_provider: github
```

Rules:

- keep `provider: supabase` to activate the feature
- `key_column` may still be named `post_path` even when the stored value is a stable `post_id`
- use `post_id` front matter when permalink stability matters

## Data Model

Recommended table:

```sql
create table if not exists public.post_comments (
  id bigint generated by default as identity primary key,
  post_path text not null,
  user_id uuid not null,
  user_name text not null,
  user_avatar_url text,
  body text not null,
  created_at timestamptz not null default now()
);
```

Recommended index:

```sql
create index if not exists post_comments_post_path_idx
on public.post_comments (post_path, created_at desc);
```

## Auth Model

Use Supabase Auth with the GitHub provider enabled.

The browser signs in with GitHub through Supabase OAuth and receives a Supabase session.

The comment table should trust `authenticated` users, not `anon`, for writes.

## RLS Model

Enable Row Level Security:

```sql
alter table public.post_comments enable row level security;
```

Minimal Stage 1 policies:

```sql
create policy "public can read comments"
on public.post_comments
for select
to anon, authenticated
using (true);

create policy "authenticated users can insert comments"
on public.post_comments
for insert
to authenticated
with check (auth.uid() = user_id);

create policy "users can delete their own comments"
on public.post_comments
for delete
to authenticated
using (auth.uid() = user_id);
```

## Post Key Strategy

Comments should use the same post identity rule as likes and pageviews:

- prefer `post_id`
- fall back to `page.url`

This keeps future permalink changes from splitting the comment thread.

## UI Model

The comment area should render below the post tail where Giscus currently appears.

It should include:

- section title
- sign-in state
- GitHub sign-in button when logged out
- textarea and submit button when logged in
- chronological comment list
- delete control for the current user's own comments

## Security and Safety

- render comment bodies as text, not raw HTML
- trim empty comments before submission
- keep delete ownership enforced by RLS
- keep the public anon key in config, never a service-role key

## Files to Update

- `_config.yml`
- `_includes/comments/supabase.html`
- `_data/locales/en.yml`
- `_data/locales/ko-KR.yml`
- `_sass/layout/post.scss`

## Verification

Structural verification:

```bash
bundle exec jekyll build --limit_posts 20
```

Functional verification:

1. load a post page
2. confirm the sign-in button renders
3. sign in with GitHub
4. add a comment
5. reload the page
6. confirm the comment is still present
7. confirm only your own comment shows a delete action

## Future Stage 2 and Beyond

- replies with parent comment ids
- moderation flags and admin hide controls
- in-app notifications
- email notifications
- push notifications through Supabase Edge Functions or another delivery layer
