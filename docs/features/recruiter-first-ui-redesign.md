# 채용 담당자 우선 UI/UX 개편 설계

작성일: 2026-09-15
전제: [콘텐츠 계획 2026-09](../project/content-plan-2026-09.md)의 Tier A~C가 끝나 콘텐츠는 준비됐다. 이 문서는 그 콘텐츠가 채용 담당자에게 실제로 닿게 하는 화면 개편을 다룬다. 콘텐츠 자체는 바꾸지 않는다.

## 1. 목표

채용 담당자가 이력서의 블로그 링크를 눌러 들어왔을 때, **3분 안에, 모바일에서도**, 다음 세 가지를 얻고 나가게 한다.

1. 이 사람이 무엇을 잘하는 사람인지 한 줄 (정합성·동시성·정산 배치를 계측으로 푸는 백엔드)
2. 그 주장을 뒷받침하는 숫자 서너 개 (2시간 → 5분, 480 → 75, 실험 26종·결함 12건)
3. 더 읽을지 결정할 근거가 되는 글 두세 편의 입구

지금 블로그는 이 세 가지를 전부 갖고 있지만, **찾아야 보인다.** 개편의 방향은 새 기능 추가가 아니라 있는 것을 첫 화면과 모바일로 끌어올리는 것이다.

## 2. 현재 상태 진단

2026-09-15 빌드를 데스크톱(1280px)과 모바일(375px)에서 확인한 결과다.

### 2.1 진입 동선이 끊겨 있다

| 발견 | 근거 | 영향 |
| --- | --- | --- |
| **채용·역량 맵 탭이 사이드바 내비게이션에서 의도적으로 제외됨** | `_includes/sidebar.html:32`에서 `/recruit/`, `/capabilities/`, `/categories/`를 `unless`로 걸러냄 | 채용 페이지로 가는 유일한 경로가 우측 패널(데스크톱 전용)과 About 하단 허브. 모바일에서는 About까지 내려가야 함 |
| **모바일에서는 우측 패널 전체가 사라짐** | Chirpy 기본 동작(xl 미만에서 `#panel-wrapper` 숨김) | "채용 담당자용", "대표 글", "핵심 역량" 패널이 폰에서 전부 안 보임. 모바일 첫 화면은 검색창 + 최신 글 목록뿐 |
| **홈에 포지셔닝 문장이 없음** | 홈 첫 화면 = 검색·필터 바 + 최신 글 카드. 사이드바 모토("Make Non Polynomial Polynomial")는 슬로건이지 역량 설명이 아님 | 이력서 링크로 들어온 사람이 "이 사람이 뭘 하는 사람인지"를 첫 화면에서 못 읽음 |
| **홈 큐레이션 include가 만들어져 있으나 연결되지 않음** | `_includes/home-curation.html`은 존재, `_layouts/home.html`에서 include 안 함, 빌드 결과 `home-curation-section` 0개 | 설계 문서(`home-curation-design.md`)의 "추천 시리즈" 섹션이 실제로는 없음 |
| **대표 글이 데스크톱에서도 폴드 아래** | 우측 패널 순서: Recently Updated → Representative Posts | 가장 신호가 강한 글이 스크롤해야 보임. Recently Updated는 채용 담당자에게 정보가 아님 |

### 2.2 글 페이지가 사례와 이력서를 연결하지 않는다

- 실무 사례 글(예: 정산 중 수정 차단)에 Problem-Decision-Result 카드가 붙어 있고 이건 좋다. 그러나 그 글이 **어느 프로젝트의 일부인지, 이력서의 어느 항목에 해당하는지, 같은 프로젝트의 다른 글이 무엇인지**가 글 안에 없다.
- About의 포트폴리오(`_data/portfolio.yml`)는 글 → 프로젝트 방향의 링크를 갖고 있지만 역방향(글에서 프로젝트로)이 없다. 검색으로 글 하나에 착지한 담당자는 그 글이 사례의 일부라는 것을 모른 채 나간다.
- 글 하단 "관련 글"은 태그 유사도 기반이라 같은 프로젝트의 글이 나온다는 보장이 없다.

### 2.3 시각 언어가 "학습 블로그"를 말한다

- 카드에 붙는 배지가 세 종류(콘텐츠 타입, 상태, 역량)이고 색이 각각 달라 신호가 분산된다. 대표 글 패널의 초록 역량 칩은 카드마다 붙어 있어 강조가 아니라 배경이 됐다.
- 본문 폰트 스택이 `Source Sans Pro`/`Lato`라 한글은 시스템 폰트로 떨어진다. 한글 본문과 라틴 숫자·코드가 서로 다른 무게로 보여 "2시간 → 5분" 같은 핵심 수치가 도드라지지 않는다.
- 아바타가 일러스트다. 이력서 가이드(`RESUME_GUIDE.md`)는 "과하지 않은 사진 하나"를 권한다. 블로그가 이력서의 연장이라면 같은 기준이 적용된다. 이건 본인 판단 사항이라 제안만 한다.
- 홈 카드가 제목·발췌·날짜·카테고리로 균일해서 TIL 한 줄과 실무 사례 글이 같은 무게로 보인다. 실무 사례 글에는 PDR 카드가 있다는 사실이 목록에서는 드러나지 않는다.

### 2.4 공유 미리보기

- `og:image`는 글에 `image`가 있을 때만 붙는다. 실무 사례 글 대부분에 이미지가 없어서 Slack이나 메신저로 링크를 공유하면 미리보기가 텍스트만 나온다. 채용 담당자 사이에서 링크가 전달되는 경로가 대부분 메신저라는 점을 감안하면 손실이 크다.

## 3. 설계 원칙

1. **있는 것을 앞으로.** 새 데이터 파일보다 `recruit_mode.yml`, `representative_posts.yml`, `portfolio.yml`을 재사용한다. 이미 세 파일이 같은 이야기를 하고 있다.
2. **모바일 우선 검증.** 모든 변경은 375px에서 먼저 확인한다. 이력서 링크는 폰에서 열린다.
3. **홈 1페이지만 특별하게.** 큐레이션·히어로는 페이지네이션 1페이지에만 두고, 2페이지부터는 지금처럼 시간순 피드로 둔다(`home-feed-ordering-policy.md`와 충돌하지 않는다).
4. **배지는 줄이고 숫자는 키운다.** 색 칩을 늘리지 않는다. 강조할 것은 before → after 수치다.
5. **Chirpy 구조를 유지한다.** 레이아웃 교체가 아니라 include 추가와 SCSS 변수 조정으로 푼다(`AGENTS.md`).
6. **읽기 경험을 해치지 않는다.** 개편은 진입 3분을 위한 것이고, 글 본문의 여백·줄 간격·코드 블록은 지금 수준을 유지한다.

## 4. 제안

우선순위는 "채용 담당자가 겪는 순서"다. 진입 → 홈 첫 화면 → 글 페이지 → 시각 정리 → 공유.

### P0. 진입 동선 (구현 반나절, 시각 변화 없음)

**P0-1. 사이드바 내비게이션에 채용 탭 노출**
`sidebar.html`의 제외 목록에서 `/recruit/`를 뺀다. 순서는 `Home · 채용 · About · Series · Types · Tags · Archives`. `/capabilities/`는 채용 페이지 안에서 링크하므로 내비에는 계속 두지 않는다. 라벨은 locale의 `tabs.recruit`를 쓴다(ko "채용", en "Recruit").

**P0-2. 모바일용 채용 담당자 카드**
`#panel-wrapper`가 숨는 xl 미만 뷰포트에서만 보이는 컴팩트 카드를 홈 1페이지 상단(검색 바 위)에 둔다. 내용은 `recruiter_panel.yml`의 `for_recruiters.links` 세 개(채용 개요, 역량 맵, 이메일)를 가로 칩으로. 데스크톱에서는 `d-xl-none`으로 숨긴다. 새 데이터 없음.

**P0-3. 우측 패널 순서 교체**
Representative Posts를 Recently Updated 위로. Recently Updated는 채용 담당자에게 정보가 아니고, 독자에게도 홈 피드가 이미 같은 정보다. 패널 4개(Representative, Trending Tags, Recently Updated, Contents) 중 Recently Updated는 글 페이지에서만 두는 것도 고려.

### P1. 홈 첫 화면 (구현 1~2일)

**P1-1. 히어로 밴드**
홈 1페이지 최상단, 검색 바 위. 구성:

```text
[eyebrow] Backend Engineer
[한 줄]   상태 전이·동시성·트랜잭션 정합성이 중요한 시스템을 계측으로 풀어온 백엔드 엔지니어
[숫자 3개] 2시간 → 5분   |   480 → 75   |   실험 26종 · 결함 12건
          80만 건 정산 배치    정적 분석 위반       ParityPay 장애 실험
[CTA]     채용 담당자용 보기 →     GitHub
```

- 한 줄 문장은 `recruit_mode.hero.title`을 재사용한다. 두 곳이 어긋나지 않게 한 소스만 쓴다.
- 숫자 3개는 새 데이터 `_data/home_hero.yml`에 `{value, label, url}`로 두되, 값은 `portfolio.yml`의 metrics와 같은 것만 쓴다. 파일을 따로 두는 이유는 "홈에 어떤 세 개를 올릴지"가 편집 결정이기 때문이다.
- 각 숫자는 해당 글로 링크한다. 숫자를 누르면 증거로 간다.
- 높이는 모바일에서 한 화면의 절반을 넘지 않는다. 숫자 3개는 모바일에서 세로 스택.
- 2페이지 이후에는 렌더링하지 않는다(`paginator.page == 1`).

**P1-2. 홈 큐레이션 연결**
`home-curation.html`을 히어로 아래에 include한다. 단, 현재 로직(`site.posts`에서 series를 만나는 순서대로 3개)은 최신 글의 시리즈가 우연히 뽑히는 구조라, `_data/home_hero.yml`에 `featured_series: [batch-structure-improvement, parity-pay, sequence-bottleneck]`을 명시하고 그 순서로 렌더링하도록 바꾼다. 카드 하나에 시리즈 제목, 편수, 한 줄 설명, "1편부터 읽기". 섹션 제목은 "여기서 시작하기".

**P1-3. 카드 위계**
홈 카드에 두 가지 신호를 추가한다.

- PDR 카드가 있는 글(`page.problem_decision_result`)에 "사례" 마커. 배지 색을 늘리지 않고, 제목 앞 작은 아이콘 하나(`fas fa-flask`류)와 카드 왼쪽 보더 색으로만 구분한다.
- 시리즈 글은 카드 메타에 "시리즈명 · n편". 지금은 카테고리만 보인다.
- 발췌는 2줄로 고정(`-webkit-line-clamp: 2`). 지금 3줄은 모바일에서 카드가 화면 하나를 차지한다.

TIL을 홈 피드에서 빼는 것은 이번 범위 밖이다. 현재 최신 글이 전부 Notes라 당장 문제가 없고, `home-feed-ordering-policy.md`가 시간순을 명시하고 있다. TIL이 다시 자주 올라오면 그때 정책을 다시 본다.

### P2. 글 페이지의 사례 문맥 (구현 1일)

**P2-1. 프로젝트 문맥 스트립**
`portfolio.yml`의 `posts` 배열을 역방향으로 조회해, 현재 글이 어느 항목에 속하면 본문 위(PDR 카드 아래)에 한 줄 스트립을 붙인다.

```text
[아이콘] 이 글은 「음원 콘텐츠 플랫폼(MCP) 전면 개편」(2024.1 – 2024.11)의 사례입니다.
         같은 프로젝트: 키 생성 병목 Part 3 · ArchUnit 가드레일    |    About에서 전체 보기 →
```

새 데이터 없이 `portfolio.yml` 하나로 About과 글 페이지가 양방향으로 연결된다. 개인 프로젝트(`personal.items`)도 같은 방식으로 "이 글은 ParityPay 시리즈의 일부입니다 · GitHub".

**P2-2. 글 하단 "다음에 읽을 것"**
현재 "관련 글"(태그 유사도)을 유지하되, 같은 프로젝트·같은 시리즈의 글을 먼저 놓고 태그 유사 글을 그 뒤에 둔다. 시리즈 글은 이미 `series-navigation.html`이 이전/다음을 제공하므로 중복되지 않게 시리즈 외 글에만 적용.

**P2-3. PDR 카드 위치**
지금은 PDR 카드가 제목 바로 아래, 본문 위에 있어 좋다. 다만 세 칸이 데스크톱에서는 한 줄, 모바일에서는 세로 스택인데, 세로 스택일 때 카드 3개가 화면 하나를 넘는다. 모바일에서는 접힌 상태(Problem만 보이고 "결정과 결과 보기" 토글)로 시작하는 것을 검토한다. 채용 담당자가 모바일에서 본문에 닿기까지 두 화면을 넘겨야 하는 것은 비용이다.

### P3. 시각 정리 (구현 1~2일, 변수 중심)

**P3-1. 한글 폰트**
본문·제목에 Pretendard(또는 Pretendard Variable)를 최우선으로 두고 기존 스택을 뒤에 남긴다. `_sass/addon/variables.scss`의 `$font-family-base`, `$font-family-heading` 두 변수만 바꾼다. 웹폰트는 jsDelivr CDN(`_data/origin/cors.yml`에 이미 CDN 패턴이 있다). 숫자는 `font-variant-numeric: tabular-nums`를 메트릭 영역에만 적용(About 포트폴리오에는 이미 적용됨).

**P3-2. 배지 정리**
- 콘텐츠 타입 배지(Notes 등)는 유지. 상태 배지는 `published`일 때 숨기고 `draft`/`archived`일 때만 보인다. "Published"는 정보가 아니다.
- 역량 칩(대표 글 패널의 초록 칩)은 패널에서 제거하고 hover 툴팁 또는 카드 하단 작은 텍스트로 격하. 채용 페이지의 대표 글 카드에서는 유지.
- 카드 보더·배경 알파를 한 단계 낮춰 카드 사이 구분을 여백으로 만든다.

**P3-3. 색 역할 정의**
현재 팔레트(보라 계열 다크)는 유지하되 역할을 셋으로 고정한다. 링크·내비 = 기존 액센트, 강조 수치(`.to`, 히어로 숫자) = 한 가지 밝은 색, 상태 = 회색 계열. `_sass/colors/typography-dark.scss`와 `typography-light.scss`에 `--metric-color` 하나만 추가한다. 라이트 모드에서 같은 위계가 유지되는지 스크린샷으로 확인한다.

**P3-4. 아바타 (본인 판단)**
일러스트를 사진으로 바꿀지는 본인이 정한다. 바꾼다면 `assets/img/avatar.jpg` 교체만으로 끝난다. 바꾸지 않는다면 채용 페이지 히어로에만 사진을 두는 절충도 가능하다.

### P4. 공유 미리보기 (구현 반나절)

**P4-1. 기본 OG 이미지**
`image`가 없는 글에는 사이트 기본 OG 이미지(`assets/img/og-default.png`, 1200×630)를 붙인다. 이미지 내용은 이름 + 한 줄 포지셔닝 + 도메인. `head.html`의 `og_image` 캡처 분기에 `default:` 하나 추가. 글별 동적 이미지 생성은 Jekyll 정적 빌드에서 비용이 커서 이번 범위 밖.

**P4-2. 채용 페이지 전용 OG**
`/recruit/`는 별도 이미지(숫자 3개 포함)를 둔다. 이력서에 블로그 링크 대신 `/recruit/`를 적을 경우를 위해서다.

## 5. 하지 않는 것

- 테마 교체, 레이아웃 3단 구조 변경. Chirpy 위에서 include와 변수로 푼다.
- 글별 OG 이미지 자동 생성, 방문 분석 대시보드, 다크·라이트 외 테마.
- TIL 피드 정책 변경(3장 P1-3 참고).
- 애니메이션·마이크로인터랙션 추가. 지금 문제는 움직임이 아니라 정보 배치다.

## 6. 위험

- **홈이 무거워진다.** 히어로 + 큐레이션 + 모바일 카드가 전부 1페이지에 얹히면 첫 화면이 길어진다. 대응: 히어로는 모바일 한 화면의 절반, 큐레이션은 카드 3개 고정, 모바일 카드는 한 줄 칩. 합쳐서 모바일 1.5화면을 넘으면 큐레이션을 뺀다.
- **`recruit_mode.hero.title`이 두 곳에 나오면 문장이 길다.** 홈 히어로용 짧은 변형(`hero.short_title`)을 `recruit_mode.yml`에 추가하고, 없으면 `title`로 폴백한다.
- **웹폰트 로딩.** Pretendard Variable은 파일이 크다(2MB대). 서브셋 버전(`pretendard-dynamic-subset`)을 쓰고 `font-display: swap`으로 FOUT를 허용한다. 오프라인 빌드에서는 폴백 스택이 그대로 동작한다.
- **배지 축소가 기존 기능 문서와 어긋난다.** `post-status-design.md`는 상태 배지를 항상 보이게 설계했다. 이 문서의 P3-2가 채택되면 그 설계 문서의 "Rendering Model" 절을 함께 고친다.

## 7. 완료 기준

- 375px 홈 첫 화면에서 스크롤 없이 포지셔닝 한 줄과 채용 페이지 진입 칩이 보인다.
- 사이드바에서 채용 페이지까지 1탭.
- 실무 사례 글 8편(시퀀스 3부, 정산 중 수정 차단, SQS, Heap Dump, ArchUnit, Shadow Release, Post-Commit, 배치 4부) 전부에 프로젝트 문맥 스트립이 붙고, About 포트폴리오 항목과 양방향으로 연결된다.
- 홈 1페이지에 추천 시리즈 3개가 편집 순서대로 나온다.
- `image` 없는 글을 메신저에 붙여 넣었을 때 기본 OG 이미지가 뜬다.
- 라이트·다크 양쪽에서 히어로 숫자, PDR 카드, 포트폴리오 메트릭의 강조색이 같은 위계로 보인다.

## 8. 순서

| 단계 | 항목 | 이유 |
| --- | --- | --- |
| 1 | P0-1, P0-2, P0-3 | 반나절에 진입 동선이 열린다. 시각 변화가 없어 리스크가 없다 |
| 2 | P2-1 | 데이터가 이미 있고, 글 → 이력서 연결이 채용 관점에서 가장 큰 단일 이득이다 |
