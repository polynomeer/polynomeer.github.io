------

### ✅ Q. 자기소개 해주시겠어요?

안녕하세요. 문제를 빠르게 인식하고 꾸준히 개선해 나가는 백엔드 개발자 [홍길동]입니다.
 대학교 시절부터 웹 서비스 개발에 흥미를 느껴 꾸준히 프로젝트와 아르바이트를 통해 실무를 익혔고, 이후 두 곳의 회사에서 음악 콘텐츠 플랫폼과 광고 시스템을 개발하며 **대규모 데이터 처리, 배치 최적화, 분산 환경에서의 API 설계**를 경험했습니다.
 현재는 더 높은 확장성과 안정성이 요구되는 환경에서 저의 역량을 발휘하고, 함께 성장할 수 있는 기회를 찾고 있습니다.

------

### ✅ Q. 컴퓨터공학과로 진학하신 이유가 있을까요?

고등학교 시절 우연히 C언어를 접하면서 코드 한 줄로 문제를 해결하는 매력에 빠졌습니다.
 스스로 웹페이지를 만들고 간단한 게임을 구현해 보며 컴퓨터공학의 세계에 흥미를 느꼈고, 그 과정에서 개발자로서의 길을 확신하게 되어 진학하게 되었습니다.

------

### ✅ Q. 입학이 12년도인데 20년에 졸업을 하셨어요, 꽤 긴 시간동안 학업을 이어갔던 이유가 있을까요?

네, 중간에 군 복무와 외부 프로젝트 참여, 그리고 다양한 인턴십 경험을 병행하다 보니 졸업이 늦어졌습니다.
 다만 그 기간 동안 실무와 가까운 다양한 경험을 쌓을 수 있었고, 오히려 전공 지식을 현실에 적용하는 능력을 키우는 데 도움이 되었다고 생각합니다.

아래는 공백 기간에 대한 질문에 **신뢰를 주면서도 성장 의지를 보여주는 답변 예시**입니다. 실제 상황에 맞게 수정해서 활용하세요.

------

### ✅ Q. 졸업하고 1년간 또 공백이 있으신데, 이때 무얼 하셨죠?

네, 졸업 이후에는 제 진로에 대해 좀 더 깊이 고민하는 시간을 가졌습니다. 단순히 개발자로 취업하는 것을 넘어서, 어떤 기술 스택을 기반으로 어떤 문제를 해결하고 싶은지를 정립하고 싶었기 때문입니다.

그 기간 동안 **기초 CS지식 복습, 프로젝트 포트폴리오 정비, Spring Boot 기반의 실전 프로젝트 제작**, 그리고 알고리즘 풀이 등을 통해 역량을 끌어올리는 데 집중했습니다.

특히 배운 내용을 바탕으로 개인 프로젝트를 GitHub에 정리하며 코드 퀄리티와 문서화 습관도 다듬었고,
 면접 준비와 동시에 기업에 맞는 기술 스택 학습도 병행하며 **지속적인 성장 기반을 마련하는 시간**이었습니다.

------

### ✅ Q. 어떤 개발자가 되고 싶으신가요?

기술적으로는 **확장성과 유지보수성에 강한 시스템을 설계할 수 있는 개발자**,
 팀워크적으로는 **문제 해결에 책임감을 가지고 끝까지 파고드는 개발자**가 되고 싶습니다.
 단순히 주어진 업무를 처리하는 것이 아니라, **기술적인 인사이트와 사용자 중심의 개선을 제안할 수 있는 개발자**가 제 목표입니다.

------

### ✅ Q. 첫 번째 회사, 두 번째 회사에서 담당하신 업무와 프로젝트를 소개해주세요.

첫 번째 회사에서는 음악 콘텐츠 플랫폼의 **메타데이터 관리, DDEX 기반 음악 유통, ISMS 대응 로깅 시스템**을 맡아 개발했습니다.
 대규모 배치 최적화, Redis 분산 락, @TransactionalEventListener 기반 이벤트 처리 등을 경험했습니다.

두 번째 회사에서는 **광고 트래킹 시스템 개선 및 실시간 리포트 API 설계**를 주도했습니다.
 Redis를 활용한 통계 수집, S3 기반 엑셀 캐싱 처리, MySQL 쿼리 최적화 등 성능 개선 중심의 업무를 진행했습니다.

------

### ✅ Q. 완전히 신규 프로젝트를 수행한 경험이 있으신가요?

네, 첫 회사에서는 **크리에이터 대상의 음악 저작권 관리 스튜디오** 신규 플랫폼을 백엔드 구조부터 설계한 경험이 있습니다.
 도메인 분석, ERD 설계, API 명세 문서화, 관리자 페이지까지 전반을 주도하였고,
 JWT 인증 및 권한 설계, Redis 캐시 전략, JPA 성능 튜닝 등을 처음부터 끝까지 맡아봤습니다.

------

### ✅ Q. 개인적인 학습은 어떻게 진행하셨나요?

평소에는 **기술 블로그에 학습 내용을 정리**하면서 지식을 체화하려고 노력하고,
 새로운 기술이 필요하거나 트러블슈팅 상황이 생기면 관련 RFC, 공식 문서를 직접 찾아보고 적용해보는 편입니다.
 또한 Udemy나 Inflearn 같은 플랫폼에서 특정 주제를 정해 집중적으로 학습하고, 이를 토이 프로젝트에 적용해 봅니다.

------

### ✅ Q. 토이 프로젝트 가장 최근에 진행한 것을 코드로 볼 수 있을까요?

네, 최근에는 [Spring Boot + Kafka 기반의 로그 수집 시스템](https://github.com/example/my-log-pipeline)을 만들었습니다.
 MDC 기반 트레이싱, JSON 로그 포맷, Filebeat 연동, Elasticsearch-Kibana 대시보드 구성까지 포함되어 있고,
 로컬에서도 재현 가능한 구조로 GitHub에 올려두었습니다. 필요하시면 링크를 공유드리겠습니다.

------

### ✅ Q. 본인의 개발자로서 부족한 점은 무엇이라고 생각하시나요?

개인적으로는 **서비스 운영 환경에서의 경험이 부족하다고 느낍니다.**
 주로 개발과 배포 직전까지의 업무에 집중해 왔기 때문에, 실제 트래픽 대응, 장애 대응 경험은 상대적으로 적었습니다.
 이를 보완하기 위해 최근에는 **Datadog, Prometheus, Sentry 등 모니터링 도구 학습**과 함께 **가상 트래픽 테스트**를 병행하고 있습니다.

------

### ✅ Q. 이 회사에 지원하신 특별한 이유가 있을까요?

이 회사는 기술적으로도 흥미롭지만, **문제를 해결하는 과정 자체를 가치 있게 여긴다는 인상을 받았습니다.**
 특히 블록체인 기반으로 신뢰성과 투명성을 강조하는 기술 방향이 제 커리어 방향성과도 잘 맞다고 느꼈습니다.
 또한, 기술 블로그나 GitHub을 통해 공개된 코드나 문서를 보면서, 개발 문화가 합리적이고 실용적이라는 인상을 받아 지원하게 되었습니다.

------

### ✅ Q. 블록체인에 대해서 좀 아시나요?

네, 기본적인 블록체인의 구조와 작동 원리(트랜잭션, 머클트리, 블록 해시, 합의 알고리즘)는 이해하고 있으며,
 실제로 Web3 기반 인증 시스템이나 EVM Smart Contract 작성도 실습해본 경험이 있습니다.
 다만 현재는 블록체인을 실서비스에 어떻게 녹여내는지, **오프체인과 온체인의 설계 균형**에 관심을 가지고 공부하고 있습니다.

------

### ✅ Q. 이 회사에 대해서 따로 조사하시거나 알고계신 내용이 있으실까요?

네, 최근 발표하신 [OOO 프로젝트]에 대해 관심 있게 보았고,
 특히 Web3 기술을 활용하되, 사용자 경험과 보안 사이의 균형을 잘 고려한 구조라는 점이 인상 깊었습니다.
 또한, 팀원들의 인터뷰나 블로그를 통해 **기술적 깊이뿐 아니라 커뮤니케이션을 중시하는 문화**도 잘 느껴졌습니다.

------

### ✅ Q. 프로젝트를 수행하시면서 개인적으로 어떤 어려움을 겪으셨나요?

주로 신규 기능이 기존 시스템과 충돌하거나, 예상치 못한 데이터 이슈가 생겼을 때 어려움을 겪었습니다.
 예를 들어, 음악 배포 플랫폼에서 신규 유통사를 연동할 때 DDEX 메타데이터 포맷이 다소 달라 기존 로직과 충돌했는데,
 이를 해결하기 위해 유연한 파싱 구조로 리팩토링하고, 테스트 케이스를 확장해 대응한 경험이 있습니다.
 그 과정에서 **정적분석 도구와 테스트 기반 개발(TDD)의 중요성**을 다시 한번 체감했습니다.

------

### ✅ Q. MBTI가 어떻게 되시나요? E라고 하셨는데, 어떤 부분에서 그렇다고 생각하시나요?

저는 ENTP입니다. 평소에도 **새로운 아이디어에 열려 있고, 다양한 관점에서 토론하며 더 나은 방향을 찾는 것**을 좋아합니다.
 회의나 코드리뷰에서도 피드백을 적극적으로 주고받으며 개선점을 찾는 스타일이고,
 개발뿐 아니라 기획/운영과도 자주 소통하면서 서비스의 완성도를 높이려고 노력합니다.

------

### ✅ Q. 이 회사에 들어오시면 어떤 기여를 할 수 있을 거라고 보시나요?

안랩블록체인컴퍼니는 **보안에 강한 블록체인 기반 인프라**를 추구하는 기업으로 알고 있습니다.
 저는 기존 커리어에서 **보안과 확장성**이라는 두 가지 키워드를 중심으로 다양한 백엔드 시스템을 개발해 왔고,
 이러한 경험을 바탕으로 ABC의 블록체인 기반 서비스에 **다음과 같은 기여**를 할 수 있다고 생각합니다.

1. **보안 중심의 서비스 설계**
    ISMS 대응을 위한 JSON 기반 로깅 시스템, MDC 트레이싱, 인증 토큰 TTL 관리, 분산락 기반 정합성 보장 로직 등을 설계한 경험이 있어
    **서비스 전반의 보안 감사 및 추적 가능성 확보**에 기여할 수 있습니다.
2. **안정성과 확장성 있는 API 및 인프라 구성**
    Spring Boot, Redis, Kafka, SQS, JPA 등을 기반으로 **분산 환경에서의 안정적인 서비스 운영 경험**이 있으며,
    블록체인과 연결되는 외부 API 연동, 트랜잭션 후크 기반 이벤트 처리 등에 있어 **신뢰성 높은 연계 로직**을 구현할 수 있습니다.
3. **블록체인 친화적 백엔드 개발자**
    개인적으로 Web3.0, EVM 기반 Smart Contract, DID, 지갑 인증 방식 등에 관심을 갖고 학습하고 있어,
    **오프체인-온체인 연계 구조 설계나 신규 서비스 기획 시에도 기술적인 소통과 기여가 가능합니다.**

무엇보다 저는 주어진 업무에만 집중하기보다는, 문제를 정의하고 더 나은 방향을 제안하는 개발자가 되고자 합니다.
 ABC에서 함께 성장하고, 보안성과 신뢰성이 중요한 Web3 시대의 기반 기술을 만드는 데 기여하고 싶습니다.

------

### ✅ Q. 최근에는 어떤 기술을 어떤 것을 통해서 학습하고 계신가요?

최근에는 **Spring Boot 3.x와 Java 21의 변화**, 그리고 **분산 시스템에서의 인증 및 캐시 전략**을 중점적으로 학습하고 있습니다.

#### 📌 학습한 기술들

- **Java 21 Virtual Thread (Project Loom)**
   기존 ThreadPool 기반 구조 대비 비용이 적고 고성능 처리가 가능하여,
   WebFlux가 필요 없는 구조에서도 동시성 처리를 개선할 수 있어 관심을 갖고 실습해보고 있습니다.
- **Spring Boot 3.x + Jakarta EE 전환 대응**
   `javax` 패키지에서 `jakarta`로의 전환에 따른 호환성 이슈를 실무 프로젝트 코드에 직접 적용하며 확인했고,
   특히 Bean Validation, JPA 관련 변경사항을 정리해봤습니다.
- **Redis 기반 세션 관리 및 TTL 인증 토큰 처리 구조 개선**
   FLO API 토큰 연동 경험을 확장하여, **AccessToken을 Redis에 저장해 TTL로 인증 상태를 관리하는 구조**를 직접 구현해보며,
   세션 상태, 만료 갱신, 보안 로그 처리까지 연결하는 구조를 실습했습니다.
