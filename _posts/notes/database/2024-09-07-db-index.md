## Database Index

### What is Index?

DB 인덱스(Database Index)는 **데이터베이스에서 검색 속도를 높이기 위해 사용하는 자료구조**이다. 마치 책의 **목차**나 **색인**처럼, 원하는 데이터를 빠르게 찾을 수 있게 해준다. 실제로 책의 인덱스 페이지에는 알파벳 순으로 정렬되어 있는데, 이는 실제 인덱스의 저장방식과 유사하다.

### 🔍 1. 인덱스가 왜 필요한가요?

일반적으로 웹 사이트나 애플리케이션을 사용할 때, 가장 많은 비중을 차지하는 부분이 **조회**이다. 따라서 삽입/삭제의 성능을 어느정도 포기하더라도 조회의 성능을 끌어올리는 것이 보통이다.

데이터베이스에서 `WHERE`, `JOIN`, `ORDER BY`, `GROUP BY` 같은 조건이 붙은 쿼리는 **해당 조건에 맞는 데이터를 빠르게 찾아야 한다.** 그런데 테이블에 수천만 건의 데이터가 있다면, 하나하나 훑는 **Full Table Scan**은 매우 느리다.

→ 이때 **인덱스가 있다면**, 해당 조건에 맞는 레코드를 빠르게 찾을 수 있습니다.

------

### ⚙️ 2. 인덱스의 동작 방식

#### ✅ 일반적인 구조: **B-Tree (또는 B+Tree)**

- 정렬된 구조를 유지하며 **이진 탐색** 방식으로 동작
- 예: `SELECT * FROM user WHERE name = 'Alice'`
  - `name` 칼럼에 인덱스가 있다면, 트리를 따라가며 `'Alice'`를 빠르게 찾음

#### ✅ 다른 구조들

| 인덱스 종류    | 설명                                            |
| -------------- | ----------------------------------------------- |
| **B-Tree**     | 범위 검색에 유리 (`<`, `>`, `BETWEEN`)          |
| **Hash**       | 정확히 일치하는 값 검색에 특화 (`=`)            |
| **Bitmap**     | boolean, enum 등 값이 적은 칼럼에 효과적        |
| **Full-text**  | 자연어 검색에 적합 (MySQL, ElasticSearch 등)    |
| **GIN / GiST** | PostgreSQL에서 JSON, 배열 등 복잡한 타입 인덱싱 |

------

### 📌 3. 인덱스의 장점과 단점

#### ✅ 장점

- **조회 속도 향상**
- **정렬, 그룹핑 효율성 향상**
- **중복 여부 확인 (`UNIQUE INDEX`)**

#### ❌ 단점

- **쓰기(INSERT/UPDATE/DELETE) 성능 저하**: 인덱스도 갱신해야 함
- **디스크 공간 추가 사용**
- **잘못된 인덱스는 오히려 성능을 악화**

------

### 🛠️ 4. 언제 인덱스를 쓰나요?

| 상황                              | 인덱스 추천 여부 |
| --------------------------------- | ---------------- |
| WHERE 조건에 자주 사용됨          | ✅ 예             |
| JOIN의 대상 칼럼이다              | ✅ 예             |
| 정렬/그룹핑 기준이다              | ✅ 예             |
| 자주 갱신되는 컬럼이다            | ❌ 주의           |
| 데이터 중복이 심하다 (boolean 등) | ❌ 효과 낮음      |

------

### ✨ 예시 (MySQL 기준)

```sql
-- 인덱스 생성
CREATE INDEX idx_user_email ON user(email);

-- 복합 인덱스
CREATE INDEX idx_user_name_age ON user(name, age);
```

복합 인덱스는 **선두 컬럼**부터 차례로 사용할 수 있다는 점에 주의!

------

필요하다면, `EXPLAIN`을 활용해 인덱스가 실제로 사용되고 있는지 확인할 수 있습니다.
 더 궁금한 점이나 인덱스 설정 실무 전략이 궁금하면 알려주세요!

## Indexing Boolean Field

boolean 필드를 인덱싱하는 것이 성능상에 이점이 있을까? 대부분의 경우에는 boolean 필드에 인덱싱을 하는 것은 의미가 없다. 하지만 이는 테이블 내 데이터의 분포에 따라 다를 수 있다. 예를 들어, 4백만 개의 데이터가 true 이고 1천개의 데이터만 false인 경우, 어떤 DBMS에서는 인덱싱으로 9초 이상의 효율을 낼 수 있다고 한다. 반면에, 사이드 이팩트로 쓰기 속도가 부분적으로 느려질 수 있다.

클러스터링 인덱스(Clustering Index)와 논 클러스터링 인덱스(Non-Clustering Index)는 **인덱스가 실제 데이터와 어떻게 연결되느냐**에 따라 구분되는 개념입니다.
 특히 **MySQL(InnoDB), SQL Server, Oracle** 등에서 성능에 큰 영향을 주는 요소입니다.

------

## 🔸 1. 클러스터링 인덱스 (Clustering Index)

### ✅ 정의

- 인덱스의 **정렬 순서대로 실제 데이터도 정렬되어 저장된 인덱스**
- 인덱스 자체가 **데이터를 담고 있음**
- 테이블에 **하나만 존재 가능** (물리적 정렬이므로)

### ✅ 예시

MySQL(InnoDB)에서 `PRIMARY KEY`가 클러스터링 인덱스입니다.

```sql
CREATE TABLE book (
  id INT PRIMARY KEY,         -- 클러스터링 인덱스
  name VARCHAR(100),
  price INT
);
```

- `id` 기준으로 데이터가 정렬되어 저장됩니다.
- 즉, `id = 100`을 찾는 작업은 **인덱스 검색 = 데이터 검색**이 됩니다.

### ✅ 장점

- **빠른 범위 조회**: 데이터가 연속된 블록에 있으므로 I/O 최소화
- **데이터 접근이 빠름**: 인덱스 → 데이터 테이블 이동이 필요 없음

### ❗ 단점

- 삽입/삭제/변경 시 **정렬 유지 비용이 듦**
- **한 개만 만들 수 있음**

------

## 🔹 2. 논 클러스터링 인덱스 (Non-Clustering Index)

### ✅ 정의

- 인덱스는 **키 + 데이터 주소(Row ID)**만 갖고 있고,
   데이터를 찾으려면 **한 번 더 테이블을 조회**해야 함
- 보조 인덱스라고도 불림

```sql
CREATE INDEX idx_name ON book(name);
```

- `name` 기준으로는 인덱스가 정렬되어 있지만,
   **실제 데이터는 정렬되어 있지 않음**

### ✅ 장점

- **여러 개 만들 수 있음**
- 특정 컬럼 기반의 조회 속도 개선

### ❗ 단점

- 인덱스 → 테이블을 다시 조회해야 해서 **추가 I/O 발생**
   (이걸 **Lookup** 또는 **Bookmark Lookup**이라고 함)

------

## 🔍 구조 비교

| 항목             | 클러스터링 인덱스           | 논 클러스터링 인덱스          |
| ---------------- | --------------------------- | ----------------------------- |
| 데이터 저장 방식 | 인덱스와 데이터가 함께 정렬 | 인덱스는 키 + Row ID (주소)   |
| 인덱스 수        | 1개만 가능 (보통 PK)        | 여러 개 가능                  |
| 성능 (단건)      | 빠름                        | 느릴 수 있음 (추가 조회 발생) |
| 성능 (범위)      | 매우 빠름                   | 느릴 수 있음                  |
| 삽입/삭제 비용   | 높음 (정렬 유지)            | 낮음                          |

------

## 💡 예시 시나리오 (MySQL InnoDB)

```sql
SELECT * FROM book WHERE id = 10;
-- 클러스터링 인덱스 사용: 곧바로 데이터 찾음 (1번 접근)

SELECT * FROM book WHERE name = 'AI Book';
-- 보조 인덱스 사용: name 인덱스 → id → 데이터 테이블 (2번 접근)
```

------
