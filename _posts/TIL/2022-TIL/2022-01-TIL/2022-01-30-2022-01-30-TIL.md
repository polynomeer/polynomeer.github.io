## Today I Learned

### GitHub Pages

GitHub Pages는 GitHub 저장소에 있는 HTML, CSS, JavaScript 파일을 그대로 가져와, 필요하면 빌드 과정을 거친 뒤 웹사이트로 게시하는 정적 사이트 호스팅 서비스다([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)). 서버를 따로 띄우지 않아도 되기 때문에 개인 기술 블로그를 시작할 때 많이 쓴다.

사이트는 두 종류다.

| 구분 | 사용자/조직 사이트 | 프로젝트 사이트 |
| --- | --- | --- |
| 소스 위치 | `<owner>.github.io` 이름의 저장소 | 프로젝트 저장소 안의 폴더 |
| 개수 제한 | 계정당 하나 | 저장소당 하나 |
| 기본 주소 | `https://<owner>.github.io` | `https://<owner>.github.io/<repositoryname>` |

블로그 용도라면 사용자 사이트로 만들고, 필요하면 커스텀 도메인을 연결한다. 정적 파일만 게시하므로 블로그 생성기는 Jekyll, Gatsby처럼 마크다운을 HTML로 바꿔 주는 도구 중에서 고르게 된다. 아래는 GitHub 블로그를 시작하는 과정을 다룬 글들이다.

### Jekyll

Jekyll은 GitHub Pages가 기본으로 지원하는 정적 사이트 생성기다. 마크다운과 HTML 파일을 레이아웃에 맞춰 완성된 정적 웹사이트로 만들고, Liquid 템플릿 언어로 반복되는 화면 조각을 채운다([About GitHub Pages and Jekyll](https://docs.github.com/en/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll)). 지금 GitHub 문서는 배포 자동화에 GitHub Actions를 권장한다.

테마는 Jekyll 블로그의 겉모습을 정하는 부분이다. [Jekyll 테마 문서](https://jekyllrb.com/docs/themes/)에 따르면 gem 기반 테마는 `_layouts`, `_includes`, `_sass`, `assets` 같은 디렉터리를 테마 gem 안에 넣어 두고, 사이트 쪽에는 보이지 않게 한다. 테마 기본값을 바꾸고 싶으면 같은 이름의 파일을 내 사이트의 `_layouts`나 `_includes`에 복사해 고치면 그 파일이 우선한다. 테마 업데이트는 `bundle update <THEME>`으로 받는다.

그래서 테마를 고를 때는 화면뿐 아니라, 내가 고칠 파일이 테마 gem 안에 있는지 내 저장소로 복사되어 있는지도 함께 봐야 한다. 복사해서 고친 파일이 많을수록 테마 업데이트를 따라가기 어려워진다.
