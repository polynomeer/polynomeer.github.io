## Today I Learned

### Redis

Redis 공식 문서는 Redis를 "data structure server"라고 소개한다. 단순히 문자열 값을 저장하는 키-값 저장소가 아니라, 값 자리에 여러 자료구조를 두고 그 자료구조에 맞는 명령을 서버에서 바로 실행한다는 뜻이다([Redis data types](https://redis.io/docs/latest/develop/data-types/)). 주요 자료구조와 대표적인 쓰임은 다음과 같다.

| 자료구조 | 설명 | 흔한 쓰임 |
| --- | --- | --- |
| String | 바이트 시퀀스. 가장 기본 타입 | 캐시, 카운터 |
| List | 삽입 순서를 유지하는 문자열 목록 | 큐, 최근 항목 |
| Set | 중복 없는 문자열 집합. 추가, 삭제, 포함 여부가 O(1) | 태그, 방문자 집합 |
| Hash | 필드-값 쌍의 모음 | 객체 한 건 저장 |
| Sorted Set | 점수 순으로 정렬된 집합 | 랭킹, 순위표 |
| Stream | append-only 로그처럼 동작 | 이벤트 기록과 소비 |

데이터를 메모리에 두기 때문에 빠르지만, 서버가 내려가면 메모리의 데이터는 사라진다. 그래서 Redis는 디스크에 남기는 방법을 두 가지 제공한다([Redis persistence](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)).

- RDB: 정해진 간격으로 데이터셋 전체의 스냅샷을 남긴다. 파일이 작고 재시작이 빠르지만, 마지막 스냅샷 이후의 변경은 잃을 수 있다.
- AOF: 서버가 받은 쓰기 명령을 모두 로그로 남기고, 재시작할 때 다시 실행해 데이터를 복원한다. 기본 정책인 매초 fsync에서는 장애가 나도 약 1초 분량만 잃는다.

문서는 PostgreSQL 수준의 안전성을 원하면 둘을 함께 쓰고, 몇 분 정도의 유실을 감수할 수 있으면 RDB만 써도 된다고 안내한다. 캐시로만 쓴다면 영속성을 아예 끄기도 한다.

키마다 만료 시간을 줄 수 있다는 점도 캐시로 많이 쓰이는 이유다. `EXPIRE`로 만료를 설정하면 시간이 지난 키는 자동으로 삭제되고, Redis는 접근 시점에 만료를 확인하는 방식과 주기적으로 일부 키를 골라 지우는 방식을 함께 쓴다([EXPIRE](https://redis.io/docs/latest/commands/expire/)).

```
SET session:42 "user-data"
EXPIRE session:42 1800
TTL session:42
```

## AI 키워드: Imagen Video

2022년 10월 5일 Imagen Video 논문이 공개됐다. 기본 영상 생성 모델 위에 공간 해상도와 시간 해상도를 번갈아 높이는 확산 모델들을 이어 붙여 고해상도 영상을 만드는 구조다. 9월 말의 Make-A-Video에 이어 텍스트로 영상을 만드는 연구가 연달아 나왔다([arXiv:2210.02303](https://arxiv.org/abs/2210.02303)).
