### Spring Boot에서 동적으로 작업 스케줄링하기

`@Scheduled`는 주기와 cron 식이 코드나 설정에 고정되어 있어서, 관리자 화면에서 작업을 등록하거나 주기를 바꾸는 요구에는 맞지 않는다. 이때는 `TaskScheduler`를 직접 쓴다. Spring 문서에 나오듯 `TaskScheduler`는 `schedule(task, trigger)`, `scheduleAtFixedRate`, `scheduleWithFixedDelay` 메서드를 제공하고 `ScheduledFuture`를 돌려준다. 이 `ScheduledFuture`를 작업 ID별로 맵에 보관해 두면 `cancel()`로 중지하고 새 `CronTrigger`로 다시 등록하는 식으로 실행 중에 스케줄을 바꿀 수 있다. `SchedulingConfigurer`를 구현하면 `@EnableScheduling`이 쓰는 레지스트라에 트리거를 직접 등록할 수도 있다. 등록한 스케줄은 메모리에만 있으므로 재시작 후에도 유지하려면 DB에 저장해 두고 시작 시 다시 등록해야 한다.

### Spring Scheduler, Quartz, Spring Batch의 차이

세 가지는 경쟁 관계가 아니라 역할이 다르다.

- Spring Scheduler(`@Scheduled`, `TaskScheduler`): 언제 실행할지를 정하는 가벼운 스케줄러다. 상태를 저장하지 않으므로 클러스터 환경에서 중복 실행을 막으려면 별도 장치가 필요하다.
- Quartz: 작업(Job)과 트리거를 DB(JobStore)에 저장할 수 있는 스케줄러다. 클러스터 모드에서 한 노드만 실행하게 하거나, 재시작 후 놓친 실행(misfire)을 처리하는 기능이 있다.
- Spring Batch: 무엇을 어떻게 처리할지를 다루는 배치 처리 프레임워크다. 청크 단위 읽기, 처리, 쓰기와 실행 이력, 재시작, 건너뛰기를 제공한다. Spring Batch 문서도 스스로를 스케줄링 프레임워크가 아니라고 밝히고, Quartz 같은 스케줄러와 함께 쓰라고 안내한다.

그래서 흔한 조합은 스케줄러(또는 Jenkins, Kubernetes CronJob 같은 외부 스케줄러)가 Spring Batch 잡을 실행하는 형태다.

### JPA의 "Found shared references to a collection" 오류

Hibernate는 엔티티의 컬렉션 필드를 자신이 관리하는 컬렉션 래퍼(`PersistentBag`, `PersistentSet` 등)로 바꿔 넣고, 각 래퍼가 어느 엔티티의 어느 필드에 속하는지 추적한다. 그런데 두 엔티티가 같은 컬렉션 인스턴스를 참조하면 flush 시점에 소유자를 하나로 정할 수 없어 이 예외가 발생한다. 흔한 원인은 엔티티를 복사하면서 `copy.setTags(origin.getTags())`처럼 컬렉션 참조를 그대로 넘기는 코드다. 해결은 참조 대신 새 컬렉션을 만들어 요소를 복사하는 것이다(`new ArrayList<>(origin.getTags())`). 연관관계가 `@ManyToMany`라면 요소 엔티티는 공유해도 되지만 컬렉션 객체 자체는 엔티티마다 따로 있어야 한다.

### JPA 프로젝션으로 Java Record 사용하기

record는 엔티티로는 쓸 수 없지만 조회 결과를 담는 DTO로는 잘 맞는다. Spring Data JPA 문서도 record가 값 의미론을 따르므로 DTO 타입을 정의하기에 적합하다고 설명한다. 리포지토리 메서드의 반환 타입을 record로 두면 클래스 기반 프로젝션으로 동작하고, JPQL에서는 생성자 표현식 `select new com.example.MemberSummary(m.id, m.name) from Member m`으로 바로 만들 수 있다. 필요한 컬럼만 조회하고 영속성 컨텍스트에 엔티티를 올리지 않으므로 읽기 전용 화면에서 유리하다.

- https://wkorando.github.io/sip-of-java/015.html
- [Projections (Spring Data JPA)](https://docs.spring.io/spring-data/jpa/reference/repositories/projections.html)
