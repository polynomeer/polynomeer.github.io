### Transaction Manager

Spring은 트랜잭션 처리를 `PlatformTransactionManager` 인터페이스로 추상화한다. JDBC는 `DataSourceTransactionManager`, JPA는 `JpaTransactionManager`, 분산 트랜잭션은 `JtaTransactionManager`처럼 기술마다 구현체가 있고, 애플리케이션 코드는 어떤 구현을 쓰든 같은 방식으로 트랜잭션을 다룬다. 트랜잭션 매니저는 시작한 커넥션(또는 EntityManager)을 현재 스레드에 바인딩해 두고, 같은 트랜잭션 안의 Repository들이 그 자원을 공유하게 한다.

이 스레드 바인딩 때문에 새 스레드를 만들어 작업을 넘기면 트랜잭션이 따라가지 않는다. 링크된 DZone 글은 여러 스레드에 걸친 트랜잭션 관리 문제를 다룬다. 선언적 방식 대신 `TransactionTemplate`으로 코드에서 경계를 직접 정하는 프로그래밍 방식도 있다.

### @Transactional

`@Transactional`은 AOP 프록시로 동작한다. 프록시가 메서드 호출을 가로채 트랜잭션 매니저로 트랜잭션을 시작하고, 정상 종료하면 커밋, 예외가 나면 롤백한다. 기본 롤백 대상은 런타임 예외와 `Error`이고, 체크 예외는 `rollbackFor`로 지정해야 롤백된다.

Spring 문서가 강조하는 함정은 자기 호출(self-invocation)이다. 프록시 모드(기본값)에서는 프록시를 거쳐 들어오는 외부 호출만 가로채므로, 같은 객체 안에서 다른 `@Transactional` 메서드를 호출하면 실제 트랜잭션이 적용되지 않는다. 또 문서는 이 문제가 롤백 시나리오를 테스트하기 전까지 드러나지 않을 수 있다고 경고한다.

### File Upload API Design

Tyk의 가이드는 파일 업로드 API를 세 방식으로 정리한다.

| 방식 | HTTP 메서드 | 쓰임 |
| --- | --- | --- |
| 직접 업로드 | PUT | 파일 하나를 바이너리 본문으로 보낸다. `Content-Type`으로 형식을 알린다 |
| 멀티파트 요청 | POST | 여러 파일, 또는 파일과 메타데이터를 한 요청에 보낸다 |
| 2단계(메타데이터 + 업로드) | POST 후 PUT | 메타데이터로 리소스를 먼저 만들고, 응답받은 위치로 파일을 올린다 |

같은 글은 클라이언트가 파일 URL만 넘기고 서버가 가져오게 하는 방식이 SSRF(서버 측 요청 위조) 위험이 있다고 지적한다. Spring MVC에서는 멀티파트를 `MultipartFile`과 `@RequestPart`로 받는다.

### AtomicInteger

`AtomicInteger`는 원자적으로 갱신할 수 있는 `int` 값이다. Javadoc은 원자적으로 증가하는 카운터 같은 용도에 쓰며 `Integer`를 대체하는 용도는 아니라고 설명한다. `incrementAndGet()`, `compareAndSet()` 같은 메서드는 락 없이 CAS(compare-and-swap) 연산으로 구현되어, 여러 스레드가 동시에 값을 올려도 갱신이 유실되지 않는다. 요청 수 집계, 시퀀스 번호 생성처럼 단일 변수의 동시 갱신이 필요할 때 `synchronized`보다 가볍게 쓸 수 있다.

- https://stackoverflow.com/questions/4818699/practical-uses-for-atomicinteger

### AOP

`@AfterThrowing` 어드바이스로 특정 포인트컷에서 던져진 예외를 가로채 로깅하거나 다른 예외로 감쌀 수 있다. `@AfterThrowing`은 예외를 관찰할 뿐 삼키지 못하므로, 예외를 바꾸거나 복구하려면 `@Around`에서 `proceed()`를 `try-catch`로 감싸야 한다. 링크된 글이 두 방식을 각각 예제로 보여 준다.

### Convert a Java Object into JSON String

lombok의 @ToString 애너테이션에 옵션값을 주어서 JSON 형식으로 오버라이딩 할 수 있으면 좋겠는데, 그런 기능은 제공하지 않는 것 같다.

### ToStringBuilder

Apache Commons Lang의 `ToStringBuilder`는 `toString()` 구현을 도와주는 유틸리티다. 출력 형식은 `ToStringStyle`로 정하는데, 3.4부터 `ToStringStyle.JSON_STYLE`이 추가되어 JSON 비슷한 형식으로 출력할 수 있다. 의존성을 하나 더 들이는 대신 Lombok 없이도 형식을 바꿀 수 있다는 점이 위 고민에 대한 하나의 답이다.

```java
@Override
public String toString() {
    return ToStringBuilder.reflectionToString(this, ToStringStyle.JSON_STYLE);
}
```

### ObjectMapper is Thread-Safe?

Jackson `ObjectMapper` Javadoc은 모든 설정이 첫 읽기나 쓰기 호출 전에 끝난다면 인스턴스가 완전히 스레드 안전하다고 설명한다. 첫 사용 이후에 설정을 바꾸면 반영이 보장되지 않고 설정 호출 자체가 실패할 수도 있다. 그래서 설정을 마친 `ObjectMapper` 하나를 static 필드나 Spring 빈으로 공유하는 것이 일반적이다. 요청마다 설정이 달라야 하면 `ObjectReader`, `ObjectWriter`를 만들어 쓴다.

### JVM Serialization

Java 직렬화 명세에 따르면 클래스의 기본 직렬화 대상은 `transient`도 `static`도 아닌 필드다. 이 기본값을 바꾸고 싶으면 `private static final ObjectStreamField[] serialPersistentFields`를 선언해 직렬화할 필드의 이름과 타입을 명시할 수 있다. 직렬화가 필요한 이유로는 객체를 파일에 저장하거나, 네트워크로 다른 JVM에 전달하거나, 세션을 복제하는 경우가 꼽힌다. ActiveJ Serializer처럼 바이트코드 생성으로 빠른 바이너리 직렬화를 제공하는 라이브러리도 있다.

## AI 키워드: ReAct

- [ReAct: Synergizing Reasoning and Acting in Language Models (arXiv 2210.03629)](https://arxiv.org/abs/2210.03629)
