### Get Empty String When Null

```java
Objects.toString(id, "");
Optional.ofNullable(id).orElse("");
StringUtils.defaultString(str).replaceAll("^(?i)null$", "");
```

Java 8 이상에서는 Optional을 사용해서 null 처리를 하는게 깔끔한 것 같다.

세 방법은 동작이 조금씩 다르다. `Objects.toString(o, "")`는 JDK 7부터 있는 표준 메서드로, `o`가 `null`이면 기본값을, 아니면 `o.toString()`을 돌려준다. `Optional.ofNullable(id).orElse("")`는 값의 타입이 이미 `String`일 때 같은 일을 한다. Commons Lang의 `StringUtils.defaultString()`은 `null`만 빈 문자열로 바꾸며, 위 예시는 여기에 더해 `"null"`이라는 문자열 자체까지 정규식으로 지운다. `Optional`은 원래 메서드 반환 타입에서 "값이 없을 수 있음"을 표현하려고 만든 것이라, 단순한 기본값 처리라면 `Objects.toString`도 충분히 깔끔하다.

- https://stackoverflow.com/questions/21936503/get-empty-string-when-null

### Servlet, HttpServletRequest

`HttpServletRequest`는 서블릿 컨테이너(Tomcat 등)가 HTTP 요청을 파싱해 만든 객체로, 요청 메서드와 URI, 헤더, 파라미터, 바디 스트림, 세션, 원격 주소 같은 정보를 제공한다. 응답은 `HttpServletResponse`로 쓴다. 컨테이너는 요청마다 이 객체를 새로 만들어 서블릿(Spring MVC에서는 `DispatcherServlet`)에 넘기고, 요청 범위의 데이터를 다음 처리 단계에 넘길 때는 `request.setAttribute()`를 쓴다.

### Logback

Logback 문서는 Logback이 `Logger`, `Appender`, `Layout` 세 클래스를 중심으로 만들어졌다고 설명한다. `Logger`는 이름 계층(보통 패키지 구조)과 레벨을 가지고 로그 이벤트를 만들고, `Appender`는 이벤트를 콘솔, 파일, 소켓 같은 목적지로 보내며, `Layout`이 이벤트를 문자열로 바꾼다. 설정 파일을 찾지 못하면 루트 로거에 `ConsoleAppender`를 붙이는 기본 설정으로 동작한다.

### Get Client IP From HttpServletRequest

```java
String ipAddress = request.getHeader("X-FORWARDED-FOR");  
if (ipAddress == null) {  
    ipAddress = request.getRemoteAddr();  
}
```

HttpServletRequest로부터 클라이언트 IP를 위와 같이 얻어올 수 있는데, FE를 통해서 들어온 IP는 FE의 IP가 찍힐 수 있다. 따라서 실제 사용자의 IP를 가져오려면 클라이언트인 FE서버가 `X-FORWARDED-FOR` 헤더에 실제 사용자의 IP를 실어서 보내주어야 한다.

MDN 문서에 따르면 `X-Forwarded-For`는 프록시를 거칠 때마다 IP가 뒤에 덧붙는 형식이라, 가장 왼쪽이 원래 클라이언트, 가장 오른쪽이 가장 최근 프록시다. 값이 `client, proxy1, proxy2`처럼 여러 개일 수 있으므로 위 코드처럼 헤더 값을 그대로 쓰지 말고 쉼표로 나눠 처리해야 한다. 또 이 헤더는 클라이언트가 임의로 넣을 수 있어서, 신뢰할 수 있는 프록시가 추가한 부분만 믿어야 한다. 서버가 인터넷에서 직접 접근 가능하면 헤더 전체가 위조될 수 있다.

- http://jmlim.github.io/java/2018/12/14/java-client-ip/
- https://stackoverflow.com/questions/29910074/how-to-get-client-ip-address-in-java-httpservletrequest

### Rolling Logs Every 15 Minutes With Logback

Logback의 `TimeBasedRollingPolicy`는 `fileNamePattern`의 날짜 형식에서 가장 작은 단위를 주기로 파일을 나눈다. `%d{yyyy-MM-dd_HH-mm}`이면 매분, `%d{yyyy-MM-dd_HH}`이면 매시간이다. "15분마다" 같은 임의 주기는 패턴만으로 표현할 수 없어서, 링크된 글은 `RollingFileAppender`를 상속해 마지막 롤오버 이후 15분이 지나면 `rollover()`를 호출하는 커스텀 Appender를 만든다.

### Spring AOP

Aspect는 공통 관심사를 모은 모듈, Advice는 실제로 실행할 코드(`@Before`, `@After`, `@Around` 등), Pointcut은 어드바이스를 적용할 위치를 고르는 표현식, JoinPoint는 어드바이스가 끼어드는 실행 지점(Spring AOP에서는 메서드 실행)이다. Spring AOP는 프록시 기반이라 같은 클래스 안에서 자기 메서드를 호출하면 어드바이스가 적용되지 않는다.

### Get Request Body With Spring Interceptor

요청 바디는 `InputStream`이라 한 번 읽으면 다시 읽을 수 없다. 인터셉터에서 바디를 읽어 버리면 이후 `@RequestBody` 변환이 실패한다. Spring의 `ContentCachingRequestWrapper`로 요청을 감싸면 읽힌 내용을 캐시해 두므로, 필터에서 래핑하고 처리가 끝난 뒤 `getContentAsByteArray()`로 바디를 꺼내 로그에 남기는 방식을 많이 쓴다.

- https://xzio.tistory.com/1999

### Unable to load io.netty.resolver.dns.macos.MacOSDnsServerAddressStreamProvider

M1에서 해당 에러가 발생하면 스프링 의존을 추가해주면 된다.

정확히는 Netty의 macOS용 네이티브 DNS 리졸버(`netty-resolver-dns-native-macos`)를 로드하지 못할 때 나오는 메시지다. 이슈 본문의 스택 트레이스에는 `osx-x86_64` 분류자 jar가 보이는데, Apple Silicon에서는 `osx-aarch_64` 분류자를 가진 의존성을 런타임에 추가하면 해결된다.

```groovy
runtimeOnly("io.netty:netty-resolver-dns-native-macos::osx-aarch_64")
```

- https://github.com/netty/netty/issues/11020
