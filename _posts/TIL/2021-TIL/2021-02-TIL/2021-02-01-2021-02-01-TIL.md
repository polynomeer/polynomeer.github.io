### Permission error

macOS에서 Wireshark로 Wi-Fi 인터페이스(`en0`)의 패킷을 캡처하려 할 때 "You don't have permission to capture on that device" 오류가 나는 경우다. 패킷 캡처는 `/dev/bpf*` 장치(BPF, Berkeley Packet Filter)를 읽어야 하는데 일반 사용자에게 권한이 없어서 생긴다. 링크의 글은 `sudo chown 사용자명 /dev/bpf*`로 장치 소유자를 바꾸는 방법을 소개한다.

### HTTP Request method

HTTP 메서드는 요청의 의도를 나타낸다. `GET`은 리소스 조회, `POST`는 데이터 제출이나 생성, `PUT`은 대상 리소스 전체 교체, `PATCH`는 부분 수정, `DELETE`는 삭제, `HEAD`는 본문 없이 헤더만 조회한다. MDN은 메서드를 안전한(safe) 메서드와 멱등(idempotent) 메서드로 구분해 설명한다. `GET`, `HEAD`는 서버 상태를 바꾸지 않아 안전하고, `PUT`, `DELETE`는 같은 요청을 여러 번 보내도 결과가 같아 멱등이지만, `POST`는 둘 다 아니다.

https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods

헤더와 본문을 나누는 기준은 HTTP 명세에 정해져 있다. 헤더는 빈 줄(`\r\n\r\n`)에서 끝나고, 그 뒤의 본문 길이는 `Content-Length` 헤더 값(바이트 수)만큼이다. 그래서 응답을 줄 단위로 읽다가 빈 줄을 만나면 헤더 파싱을 멈추고, `Content-Length`만큼 바이트를 더 읽으면 된다. 문자 단위가 아니라 바이트 단위라는 점, 그리고 `Transfer-Encoding: chunked` 응답에는 `Content-Length`가 없다는 점을 함께 처리해야 한다.

### How to send a raw HTTP request vis Java

HTTP는 TCP 위의 텍스트 프로토콜이므로, `Socket`으로 서버의 80번 포트에 연결해 요청 메시지를 직접 써 보내도 된다. 첫 번째 글이 이 방식이다. 요청 줄과 헤더는 CRLF(`\r\n`)로 끝나야 하고, HTTP/1.1에서는 `Host` 헤더가 필수다.

```java
try (Socket socket = new Socket("example.com", 80)) {
    PrintWriter out = new PrintWriter(socket.getOutputStream());
    out.print("GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n");
    out.flush();
    BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
    in.lines().forEach(System.out::println);
}
```

실무 코드에서는 직접 소켓을 다루기보다 `HttpURLConnection`이나 Java 11의 `HttpClient`를 쓴다. Baeldung 글은 `HttpURLConnection`으로 메서드, 헤더, 파라미터를 설정하고 응답 코드와 본문을 읽는 방법을 정리한다.
