## JdbcTemplate이 대신해 주는 일

순수 JDBC로 쿼리 하나를 실행하려면 `DriverManager`나 `DataSource`에서 커넥션을 얻고, `PreparedStatement`를 만들고, 값을 바인딩하고, `ResultSet`을 돌며 객체로 옮기고, 마지막에 세 자원을 모두 닫아야 한다. 링크한 MySQL Connector/J 문서의 예제가 바로 이 흐름이다.

`JdbcTemplate`은 이 중 반복되는 부분을 맡는다. [Spring 문서](https://docs.spring.io/spring-framework/reference/data-access/jdbc/core.html)에 따르면 자원의 생성과 해제를 처리해서 커넥션을 닫지 않는 실수를 막고, JDBC의 `SQLException`을 `org.springframework.dao` 패키지의 `DataAccessException` 계층으로 바꿔 준다. 애플리케이션 코드는 SQL과 결과를 객체로 옮기는 방법만 제공하면 된다.

```java
// 단일 값
int count = jdbcTemplate.queryForObject("select count(*) from room", Integer.class);

// 한 행을 객체로
Room room = jdbcTemplate.queryForObject(
        "select id, location from room where id = ?",
        (rs, rowNum) -> new Room(rs.getLong("id"), rs.getString("location")),
        1L);

// 변경
jdbcTemplate.update("insert into room (location) values (?)", "서울");
```

## 알아 둘 점

- `queryForObject`는 결과가 정확히 한 행이어야 한다. 0행이거나 여러 행이면 `IncorrectResultSizeDataAccessException`을 던지므로([JdbcTemplate Javadoc](https://docs.spring.io/spring-framework/docs/5.3.x/javadoc-api/org/springframework/jdbc/core/JdbcTemplate.html)), 없을 수 있는 조회는 `query`로 리스트를 받아 비었는지 확인한다.
- `?` 자리표시자가 많아지면 순서를 헷갈리기 쉽다. `NamedParameterJdbcTemplate`을 쓰면 `:location`처럼 이름으로 바인딩할 수 있다.
- 문서에 따르면 `JdbcTemplate` 인스턴스는 한 번 설정하면 스레드 안전하다. 그래서 DAO마다 새로 만들 필요 없이 빈 하나를 주입받아 공유한다. Spring Boot는 `JdbcTemplate`과 `NamedParameterJdbcTemplate`을 자동 구성하므로 생성자로 바로 주입받으면 된다([Spring Boot 문서](https://docs.spring.io/spring-boot/reference/data/sql.html)).
