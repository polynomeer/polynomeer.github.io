## MySQL

### How to rollback last query

MySQL은 기본적으로 autocommit 모드로 동작한다. 트랜잭션을 따로 열지 않으면 문장 하나하나가 `START TRANSACTION`과 `COMMIT`으로 감싸진 것처럼 실행되고, 끝난 문장은 `ROLLBACK`으로 되돌릴 수 없다. 그래서 이미 실행한 `UPDATE`나 `DELETE`를 취소하는 명령은 없다. 되돌리려면 백업이나 바이너리 로그에서 복구해야 한다.

위험한 수정을 할 때는 실행 전에 트랜잭션을 먼저 연다. 결과를 확인하고 나서 `COMMIT`이나 `ROLLBACK`을 고르면 된다.

```sql
START TRANSACTION;
UPDATE orders SET status = 'CANCELED' WHERE id = 42;
SELECT * FROM orders WHERE id = 42;  -- 결과 확인
ROLLBACK;                            -- 또는 COMMIT
```

이 방법도 만능은 아니다. 데이터베이스나 테이블을 만들고 지우고 바꾸는 DDL은 롤백되지 않는다. 트랜잭션 중간에 DDL을 실행하면 그 앞의 변경까지 되돌릴 수 없게 될 수 있다.

- https://stackoverflow.com/questions/2839269/how-to-rollback-the-effect-of-last-executed-mysql-query

### MySQL backup and restore

`mysqldump`는 논리 백업 도구다. 테이블 정의와 데이터를 다시 만들어 낼 수 있는 SQL 문으로 덤프하고, 복원은 그 파일을 `mysql` 클라이언트로 실행하면 된다. InnoDB 테이블이라면 `--single-transaction`을 붙여서 테이블을 잠그지 않고 한 시점의 일관된 스냅숏을 덤프할 수 있다.

```bash
mysqldump -u user -p --single-transaction mydb > mydb.sql
mysql -u user -p mydb < mydb.sql
```

## Spring

### @Scheduled

`@Scheduled`의 주기 옵션은 세 가지다.

| 옵션 | 기준 | 예 |
| --- | --- | --- |
| `fixedDelay` | 이전 실행이 끝난 시점부터 잰다 | `@Scheduled(fixedDelay = 5000)` |
| `fixedRate` | 이전 실행이 시작된 시점부터 잰다 | `@Scheduled(fixedRate = 5000)` |
| `cron` | cron 표현식으로 시각을 지정한다 | `@Scheduled(cron = "0 15 9-17 * * MON-FRI")` |

작업이 주기보다 오래 걸릴 수 있다면 `fixedDelay`가 안전하다. 실행 사이에 항상 간격이 보장되기 때문이다. Spring의 cron 표현식은 리눅스 crontab과 달리 초 필드로 시작하는 6개 필드(초 분 시 일 월 요일)를 쓰고, `zone` 속성으로 타임존을 지정할 수 있다. `initialDelay`를 주면 첫 실행을 그만큼 늦춘다.

### Assert

`org.springframework.util.Assert`는 메서드 인자를 검증하는 유틸리티다. 조건이 맞지 않으면 대부분 `IllegalArgumentException`을 던지고, `Assert.state`는 `IllegalStateException`을 던진다. 설정 오류가 아니라 프로그래머의 실수를 일찍 드러내기 위한 도구다.

```java
Assert.notNull(userId, "userId must not be null");
Assert.isTrue(amount > 0, "amount must be positive");
```

Javadoc은 이 클래스가 주로 프레임워크 내부용이고, 더 풍부한 검증 도구가 필요하면 Apache Commons Lang의 `Validate`나 Guava의 `Preconditions`를 고려하라고 안내한다.

## AI 키워드: ALiBi

Transformer가 학습 때보다 긴 입력을 추론 시점에 처리하게 만드는 위치 표현 방법인 ALiBi(Attention with Linear Biases)가 발표됐다. 단어 임베딩에 위치 임베딩을 더하는 대신, 어텐션 점수에 두 토큰 사이 거리에 비례하는 감점을 주는 방식이다. 논문 제목 "Train Short, Test Long"이 의도를 그대로 설명한다.
