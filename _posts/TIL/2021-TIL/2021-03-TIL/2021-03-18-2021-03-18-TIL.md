파일을 지우는 커밋을 새로 만들어도 그 파일은 이전 커밋들의 스냅샷에 그대로 남아 있다. 저장소 이력에서 파일을 완전히 없애려면 그 파일이 들어 있는 모든 커밋을 다시 써야 한다. 최근 커밋 몇 개라면 `git rebase -i`로 고칠 수 있지만, 이력 전체에서 특정 파일을 지우려면 BFG Repo-Cleaner 같은 전용 도구가 편하다.

BFG 문서가 안내하는 순서는 다음과 같다.

1. `git clone --mirror`로 저장소를 bare 형태로 복제한다.
2. `java -jar bfg.jar --delete-files <파일> <저장소>.git`처럼 BFG를 실행해 이력을 다시 쓴다.
3. `git reflog expire --expire=now --all && git gc --prune=now --aggressive`로 더 이상 참조되지 않는 객체를 실제로 지운다.
4. 원격 저장소에 푸시한다.

첫째, `Protected commits` 경고다. BFG는 기본적으로 현재 브랜치의 최신 커밋(HEAD)은 건드리지 않는다. 문서에 따르면 최신 커밋은 실제로 배포되는 코드일 가능성이 높아서, 그 안의 파일을 지우면 동작이 깨질 수 있기 때문이다. 그래서 HEAD 커밋 `5803b18a`에 지우려는 파일이 들어 있으면, 그 이전 커밋들에서는 지워도 HEAD에는 남는다는 경고가 나온다. 완전히 지우려면 출력의 안내대로 파일을 지우는 커밋을 먼저 만든 뒤, 새로 복제한 저장소에 BFG를 다시 실행해야 한다.

둘째, 첫 `git push --force`가 `fatal: not a git repository`로 실패했다. bare 저장소는 `polynomeer.github.io.git` 디렉터리 자체가 Git 저장소이고 상위 디렉터리는 저장소가 아니므로, 그 디렉터리 안으로 들어가서 푸시해야 한다. 디렉터리를 옮긴 뒤의 푸시는 `main -> main (forced update)`로 성공했다.

GitHub 문서는 이 작업에 대해 몇 가지를 경고한다. 이력을 다시 쓰면 그 파일을 처음 넣은 커밋과 그 뒤의 모든 커밋 해시가 바뀐다. 또 이미 다른 사람이 복제했거나 포크한 저장소에는 데이터가 남아 있을 수 있다. 지우려는 것이 비밀번호나 키 같은 비밀 정보라면, 이력을 고치기 전에 그 값을 먼저 폐기하거나 교체하라고 권한다.

### textarea 기본값

- [How to add default value for HTML textarea? - Stack Overflow](https://stackoverflow.com/questions/6007219/how-to-add-default-value-for-html-textarea)

`<input>`은 `value` 속성으로 기본값을 주지만, `<textarea>`는 여는 태그와 닫는 태그 사이의 내용이 기본값이다. HTML 표준은 textarea의 초기화(reset) 동작을 원래 값(raw value)을 요소의 자식 텍스트 내용으로 되돌리는 것으로 정의한다.

```html
<textarea name="contents">기본으로 들어갈 내용</textarea>
```

태그 사이의 공백도 값에 들어간다. HTML 파서는 여는 태그 바로 뒤에 오는 줄바꿈 하나만 편의상 무시하므로, 그 뒤에 들여쓰기 공백을 넣으면 공백까지 기본값이 된다.

## AI 키워드: SEER

2021년 3월 Facebook AI 연구진이 SEER 논문을 arXiv에 올렸다. 그동안의 자기 지도 학습은 잘 정리된 ImageNet으로 실험했는데, SEER는 정리되지 않은 무작위 이미지 10억 장으로 13억 파라미터 모델을 라벨 없이 학습했다. 논문은 GPU 512개로 학습한 이 모델이 ImageNet top-1 정확도 84.2%를 기록해, 기존 최고의 자기 지도 학습 모델보다 1% 높았다고 보고한다.
