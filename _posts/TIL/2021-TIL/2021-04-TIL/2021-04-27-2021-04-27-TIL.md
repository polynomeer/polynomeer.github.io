# 2021-04-27-TIL

## HashMap to List using Stream

- https://stackoverflow.com/questions/29625529/hashmap-with-streams-in-java-8-streams-to-collect-value-of-map

`Map` 자체는 스트림을 만들지 않으므로 `values()`, `keySet()`, `entrySet()` 중 하나에서 스트림을 연다.

```java
List<Item> items = itemMap.values().stream()
        .filter(item -> item.isOnSale())
        .collect(Collectors.toList());
```

[`Collectors.toList()`](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/stream/Collectors.html#toList())는 반환하는 `List`의 구현 타입이나 변경 가능 여부를 보장하지 않는다. 특정 구현이 필요하면 `toCollection(ArrayList::new)`를 쓴다. 반대로 리스트를 맵으로 모으는 `toMap`은 키가 중복되면 `IllegalStateException`을 던지므로, 중복 가능성이 있으면 병합 함수를 받는 오버로드를 써야 한다.

## 커스텀 예외

- https://devbox.tistory.com/entry/Java-%EC%98%88%EC%99%B8-%EB%A7%8C%EB%93%A4%EA%B8%B0
- https://woowacourse.github.io/javable/post/2020-08-17-custom-exception/
- https://kihoonkim.github.io/2017/09/09/java/noexception-in-stream-operations/

커스텀 예외를 만들 때 먼저 정할 것은 checked로 할지 unchecked로 할지다. Java 튜토리얼의 기준은 "If a client can reasonably be expected to recover from an exception, make it a checked exception."(호출자가 예외에서 회복할 수 있다고 기대할 만하면 checked로 만든다)이다([Oracle Java Tutorials](https://docs.oracle.com/javase/tutorial/essential/exceptions/runtime.html)). 같은 글은 단지 `throws` 선언이 귀찮다는 이유로 `RuntimeException`을 상속하지 말라고도 적는다.

`ItemNotFoundException`처럼 도메인 상황이 이름에 드러나는 예외를 만들면, 표준 예외(`IllegalArgumentException` 등)보다 로그와 예외 처리 코드에서 의도를 읽기 쉽다. 세 번째 글은 스트림 람다 안에서 checked 예외를 다루는 문제를 다룬다. `Function.apply` 같은 함수형 인터페이스 메서드는 checked 예외를 선언하지 않으므로, 람다 안에서 던지려면 감싸서 unchecked로 바꿔야 한다.

## @ResponseStatus

- https://www.baeldung.com/spring-response-status

`@ResponseStatus`는 핸들러 메서드나 예외 클래스에 붙여서 응답 상태 코드를 지정한다([Spring Javadoc](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/web/bind/annotation/ResponseStatus.html)).

```java
@ResponseStatus(HttpStatus.NOT_FOUND)
public class ItemNotFoundException extends RuntimeException { }
```

주의할 점이 있다. 예외 클래스에 붙이거나 `reason` 속성을 쓰면 Spring은 `HttpServletResponse.sendError`를 호출한다. 그러면 서블릿 컨테이너가 HTML 오류 페이지를 쓰는 경우가 많아서 REST API의 JSON 오류 응답과 맞지 않는다. Javadoc도 이런 경우에는 `ResponseEntity`를 반환 타입으로 쓰는 편이 낫다고 안내한다.
