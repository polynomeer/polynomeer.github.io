## Nginx

- https://velog.io/@wijihoon123/Nginx%EB%9E%80-%EB%AC%B4%EC%97%87%EC%9D%B8%EA%B0%80

nginx는 마스터 프로세스 하나와 여러 워커 프로세스로 동작한다. 마스터는 설정을 읽고 워커를 관리하며, 실제 요청은 워커가 처리한다([nginx Beginner's Guide](https://nginx.org/en/docs/beginners_guide.html)). 웹 서버로 정적 파일을 내보낼 수도 있고, 받은 요청을 뒤쪽 애플리케이션 서버로 넘기는 프록시로도 쓸 수 있다.

```nginx
server {
    location / {
        proxy_pass http://localhost:8080;
    }

    location /images/ {
        root /data;
    }
}
```

위 설정은 `/images/`로 시작하는 요청은 `/data/images/` 아래 파일로 직접 응답하고, 나머지는 8080 포트의 애플리케이션으로 넘긴다. nginx는 요청 URI와 가장 길게 일치하는 `location`을 고른다. 설정을 바꾼 뒤에는 `nginx -s reload`로 다시 읽게 하면, 마스터가 새 설정을 검사하고 새 워커를 띄운 뒤 기존 워커를 순서대로 내린다. 그래서 Spring Boot 앞에 nginx를 두면 정적 파일 응답과 요청 분배를 애플리케이션 밖에서 맡길 수 있다.

## EC2 SSH 접속 오류

https://aws.amazon.com/ko/premiumsupport/knowledge-center/ec2-linux-resolve-ssh-connection-errors/

EC2 인스턴스에 SSH로 붙지 못할 때 AWS 문서가 먼저 확인하라고 하는 항목은 다음과 같다([EC2 연결 문제 해결](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/TroubleshootingInstancesConnecting.html)).

- 사용자 이름: AMI마다 기본 사용자가 다르다. Amazon Linux는 `ec2-user`, Ubuntu는 `ubuntu`다.
- 보안 그룹: 인바운드 규칙에 내 IP에서 22번 포트로 들어오는 SSH 트래픽이 허용되어 있어야 한다. `Connection timed out`이면 대개 이 문제다. 집이나 카페처럼 IP가 바뀌는 환경에서는 규칙에 적은 IP가 더 이상 내 IP가 아닐 수 있다.
- 키 파일 권한: 개인 키 파일을 다른 사용자도 읽을 수 있으면 SSH가 `UNPROTECTED PRIVATE KEY FILE` 경고와 함께 키를 무시한다. `chmod 400 key.pem`으로 권한을 줄인다.
- 키 짝: `Permission denied (publickey)`이면 인스턴스를 만들 때 고른 키 페어의 개인 키를 쓰고 있는지 확인한다.
