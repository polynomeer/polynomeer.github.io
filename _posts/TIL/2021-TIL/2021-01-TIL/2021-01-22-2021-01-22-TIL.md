## 운영체제의 목적과 가상 메모리

OS의 목적 HW제어, Protection 리소스 보호

VM 가상메모리 - 콘도 overbooking과 비슷, 페이징

요구 페이징 시스템은 프로세스가 특정 페이지를 요구할 때 그 페이지를 물리 메모리에 올린다. 필요한 페이지가 메모리에 없으면 페이지 부재(page fault)가 나고, 빈 프레임이 없으면 내보낼 페이지를 골라야 한다. 참고한 글은 이 선택 기준으로 가장 오래 전에 올라온 페이지를 내보내는 FIFO, 앞으로 가장 오래 쓰이지 않을 페이지를 내보내는 최적(Optimal) 교체, 가장 오래 사용되지 않은 페이지를 내보내는 LRU를 비교한다. 최적 교체는 미래의 참조를 알아야 하므로 실제 구현보다 비교 기준으로 쓰인다.

## fork, exec, source

`fork()`는 호출한 프로세스를 복제해 새 프로세스를 만든다. 아래처럼 무한히 `fork()`하는 코드는 프로세스 테이블을 가득 채운다. 메모에는 `for()`로 적혀 있었는데 `fork()`의 오타다.

```c
while (true) {
    int pid = fork(); // 65500 정도로 제한하면 ssh로 접속해서 kill할 수 있다.
}
```

스미스 요원이 fork() 해서 막 복제한 다음 exec()하는 것. 컴퓨터 공부를 하고 다시 보는 영화를 리뷰 해야지.

연산이 많지 않아서 부모가 먼저 죽을 가능성이 크다. 핵심 연산은 자식이 담당하므로

export $PYRO

source 명령은 출력된다. source는 한 줄씩 명령을 현재 쉘에서 실행하는 것이다. 그러므로 fork()를 하지 않는다. `. test.sh` 점은 source의 준말이다.

Bash 매뉴얼은 `.` 명령이 파일의 명령을 현재 셸 컨텍스트에서 읽어 실행한다고 설명하고, `source`를 `.`의 동의어로 정의한다. 반면 실행 권한이 있는 스크립트를 그냥 실행하면 Bash가 자기 자신의 새 인스턴스(서브셸)를 만들어 실행하므로 그 안에서 바꾼 환경 변수가 부모 셸에 남지 않지만, `source`로 실행하면 현재 셸의 변수가 바뀐다.

## 스레드의 구조와 스케줄링

스레드는 preempt 하는가?

파직스(POSIX) 스레드

스레드의 확대 -> PC와 Register Backup이 필요, 메모리의 코드영역은 공유한다, 스택은 나눠서 각자 쓴다, 힙은 공유

`pthreads(7)` 매뉴얼도 같은 구조를 설명한다. 한 프로세스의 스레드들은 같은 프로그램을 실행하고 전역 메모리(데이터와 힙 세그먼트)를 공유하지만, 스레드마다 자기 스택을 가진다.

리눅스가 프로세스를 스케줄링하는지 스레드를 스케줄링하는지에 대한 Stack Overflow 답변은, 리눅스 스케줄러의 단위가 태스크이고 멀티스레드 프로세스의 각 스레드도 싱글스레드 프로세스와 같은 방식으로 스케줄링된다고 설명한다. Java 스레드가 유저 영역과 커널 영역 중 어디에 만들어지는지는 JVM 구현마다 다르다는 답변이 달려 있다.

## Java의 모니터와 동기화

JLS 17장에 따르면 Java의 기본 동기화 수단은 모니터다. 모든 객체는 모니터와 연결되어 있고, 한 번에 한 스레드만 모니터의 락을 가질 수 있으며 다른 스레드는 락을 얻을 때까지 블록된다. `synchronized` 블록이 이 락을 사용하고, `wait()`와 `notify()`도 객체의 모니터를 통해 스레드끼리 신호를 주고받는다.

`wait()`는 `Object`의 메서드라서 `synchronized` 문맥 안에서 호출해야 하고, 그렇지 않으면 `IllegalMonitorStateException`이 난다. `join()`은 `Thread`의 메서드로, 호출 대상 스레드가 끝날 때까지 현재 스레드를 기다리게 해 실행 순서를 정한다.

뮤텍스는 열쇠 하나를 가진 스레드만 공유 자원에 들어가는 방식이고, 세마포어는 공유 자원에 동시에 접근할 수 있는 수를 값으로 두고 그 값을 줄이고 늘려 상호 배제를 이루는 방식이다.

## Node.js 이벤트 루프

Node.js 문서에 따르면 이벤트 루프는 JavaScript 스레드가 기본적으로 하나뿐인데도 논블로킹 I/O를 할 수 있게 해 주는 장치이고, 가능한 작업은 커널에 넘긴다. 루프는 `setTimeout()`과 `setInterval()` 콜백을 실행하는 timers, 새 I/O 이벤트를 받아 콜백을 실행하는 poll, `setImmediate()` 콜백을 실행하는 check, close 콜백 단계 등을 차례로 돈다. 그래서 콜백 하나가 오래 걸리면 다음 단계의 타이머 콜백도 늦어진다.
