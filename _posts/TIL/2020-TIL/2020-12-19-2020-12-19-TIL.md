### 왜 두 버전이 같아야 하는가

`vue-template-compiler`는 `.vue` 파일의 `<template>`을 미리 렌더 함수로 컴파일하는 패키지다. README는 대부분의 경우 `vue-loader`와 함께 쓰게 된다고 설명한다. 컴파일러가 만든 렌더 함수는 런타임 패키지인 `vue`가 실행하므로, 둘의 버전이 다르면 컴파일러가 만든 코드를 런타임이 기대와 다르게 해석할 수 있다.

그래서 이 패키지는 로드되는 순간 버전을 직접 검사한다. v2.6.12 태그의 [`packages/vue-template-compiler/index.js`](https://github.com/vuejs/vue/blob/v2.6.12/packages/vue-template-compiler/index.js)는 `require('vue').version`과 자기 `package.json`의 버전을 비교하고, 하나라도 다르면 위 메시지를 담은 `Error`를 던진다.

```js
if (vueVersion && vueVersion !== packageVersion) {
  // ...
  throw new Error('\n\nVue packages version mismatch:\n\n' + /* ... */)
}
```

비교가 `!==`이므로 메이저나 마이너만 맞아서는 안 되고 패치 버전까지 정확히 같아야 한다. 이번에는 `vue@2.6.12`와 `vue-template-compiler@2.5.17`로 마이너 버전부터 달랐다.

### npm update가 해결하지 못하는 경우

메시지는 `vue-loader@>=10.0`을 쓴다면 `vue-template-compiler`만 업데이트하면 된다고 안내한다. 다만 npm 문서에 따르면 `npm update`는 `package.json`에 적힌 semver 범위를 지키는 안에서만 최신 버전으로 올린다. 예를 들어 `^2.5.17`이면 2.x 안에서 올라가지만, `2.5.17`처럼 버전을 고정해 두었다면 그대로 남는다. 그때는 `npm install vue-template-compiler@2.6.12 --save-dev`처럼 `vue`와 같은 버전을 직접 지정해야 한다.
