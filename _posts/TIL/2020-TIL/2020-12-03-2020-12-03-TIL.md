## Connect mysql to JDBC

Java 애플리케이션에서 MySQL에 JDBC로 연결하는 방법을 찾아봤다. `Class.forName()`으로 드라이버 클래스를 로딩하면 드라이버 객체가 만들어져 `DriverManager`에 등록되고, 그다음 `DriverManager.getConnection()`으로 커넥션을 얻는다. MySQL 서버 쪽 설정은 `my.cnf` 파일에서 바꾸므로, 이 파일의 역할과 macOS에서의 위치도 함께 확인했다.

## MySQL TimeZone problem

MySQL Connector/J로 연결할 때 다음과 같은 에러가 날 수 있다.

> The server time zone value 'KST' is unrecognized or represents more than one time zone. You must configure either the server or JDBC driver (via the serverTimezone configuration property) to use a more specifc time zone value if you want to utilize time zone support.

서버의 타임존 값을 드라이버가 해석하지 못해서 생기는 문제이고, 서버 설정을 바꾸거나 JDBC URL에 `serverTimezone`을 지정해 해결한다. 참고한 글은 URL 뒤에 `?characterEncoding=UTF-8&serverTimezone=UTC`를 붙이는 방법을 보여 준다. XML 설정 파일에 URL을 적는 경우 `&`를 `&amp;`로 써야 한다는 점도 함께 짚는다.

## java.sql.SQLException: Before start of result set

`ResultSet`의 커서는 처음에 첫 번째 행 앞에 있다. `next()`를 처음 호출해야 첫 번째 행이 현재 행이 되므로, `next()`를 부르기 전에 값을 읽으면 이 예외가 난다.

로그인 프로세스에서 ResultSet에 대한 null 체크과정과 로그인 시도할 때 마다 User Bean 객체의 초기화가 필요하다.

## java.awt.IllegalComponentStateException

java.awt.IllegalComponentStateException: component must be showing on the screen to determine its location

`Component.getLocationOnScreen()`은 컴포넌트의 왼쪽 위 모서리를 화면 좌표로 돌려주는데, 컴포넌트가 화면에 보이지 않는 상태면 `IllegalComponentStateException`을 던진다. 창이 표시되기 전에 화면 위치를 묻는 코드에서 이 예외가 난다.

## JTable 다루기

How to get selected row in JTable?

To get multiple selected rows in JTable

`JTable.getSelectedRow()`는 선택된 첫 번째 행의 인덱스(선택이 없으면 -1)를, `getSelectedRows()`는 선택된 모든 행의 인덱스를 돌려준다.

How to hide column in JTable?

`JTable.removeColumn()`은 `JTable`의 컬럼 배열에서 컬럼을 빼지만 모델의 데이터는 그대로 둔다. 그래서 화면에서는 숨기고 모델에서는 값을 계속 읽을 수 있다.

## java.sql.SQLException: Can not issue data manipulation statements with executeQuery()

SELECT를 제외한 나머지 쿼리문은 리턴값으로 int의 값을 반환하는 executeUpdate() 사용해야 한다.

`Statement` Javadoc 기준으로 `executeQuery()`는 `ResultSet` 하나를 돌려주는 SQL을 실행하고, `executeUpdate()`는 `INSERT`, `UPDATE`, `DELETE`나 DDL처럼 결과 집합이 없는 SQL을 실행한다.
